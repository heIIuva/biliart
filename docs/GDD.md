## 1. Концепция (коротко)

**Жанр:** бильярд 8-ball (копия механики мобильного 8 Ball Pool, но без бренда, названий и интерфейса Miniclip) + идл-прогрессия + мемная «китайская мобильная» подача.

**Мем-основа:** «Hu Hu Sheng Wei» (虎虎生威 — «могучий как тигр»). В китайских мобильных бильярдных играх за особый удар на весь экран выскакивает заставка с тигром и иероглифами, а комментатор кричит. Наша фишка — **гипертрофированный пафос вокруг каждого удара**: титулы с иероглифами, рёв тигра, замедление, тряска камеры. Плюс смешные провалы.

**Столпы игры:**
1. **Бильярд — ядро.** Физика должна ощущаться хорошо: винт, оттяжка, накат, точный прицел. Если удар ощущается плохо, ничего не спасёт.
2. **Система хайпа.** Каждый удар классифицируется и получает титул (или антититул) с заставкой. Это главный источник клипов.
3. **Клипабельность.** Режим повтора в вертикальном формате 9:16 для рилсов, видимые аватары, водяной знак с названием игры.
4. **Удержание.** Коллекция «духов ударов», своя бильярдная-додзё с пассивным доходом, ребёрт, ежедневные задания, события.
5. **Мемо-независимость.** Тигр — стартовый «скин» системы хайпа. Титулы, заставки, звуки и тексты задаются данными (конфиг + live-конфиг), чтобы новый мем добавлялся за день без переписывания кода.

**Платформы:** приоритет — мобильные (горизонтальная ориентация), также ПК. Консоли — не в приоритете, но не ломать.

## 4. Физика бильярда (`PoolPhysics`)

**Встроенную физику Roblox для шаров НЕ используй.** Шары в мире — `Anchored` Part'ы, которые клиент двигает по рассчитанной сервером траектории.

### 4.1. Модель

- Единицы — **метры и секунды** внутри симуляции. Переводной коэффициент в студы — в `Config.Physics.StudsPerMeter`.
- Стол — плоскость XY. У каждого шара: позиция `(x, y)`, высота `z` (для прыжков), скорость `(vx, vy, vz)`, угловая скорость `(wx, wy, wz)`, состояние: `Stationary | Sliding | Rolling | Spinning | Airborne | Pocketed`.
- Стартовые значения (все в `Config.Physics`, подбираются по ощущениям):
  - радиус шара ≈ 0.028575 м (диаметр 57.15 мм), масса одинаковая;
  - игровое поле: вариант `Standard` 2.24 × 1.12 м (пропорция 2:1, как в мобильных играх); вариант `Chinese8` — того же размера, но с более узкими лузами (параметр);
  - коэффициент трения скольжения ≈ 0.2, качения ≈ 0.01, трения вращения (spin) ≈ 0.044 · радиус;
  - упругость шар-шар ≈ 0.95, шар-борт ≈ 0.75–0.8;
  - максимальная скорость битка ≈ 9–10 м/с (сила 1.0).
- Классическая модель «скольжение → качение»: после удара биток скользит, трение переводит его в чистое качение. От этого зависят накат (верхний винт) и оттяжка (нижний винт) — **это критично для ощущений**, сделай аккуратно.
- **Удар кием:** входные параметры `angle` (рад), `power` (0..1), `spinX`, `spinY` (точка удара по битку, в единичном круге, радиус ограничен `Config.Physics.MaxTipOffset`), `elevation` (угол подъёма кия, 0..`MaxElevation`). Из них считаются начальные линейная и угловая скорости битка.
- **Столкновения шар-шар:** упругие, равные массы, с небольшой потерей энергии; передача части вращения (упрощённо — достаточно, чтобы оттяжка/накат работали после столкновения).
- **Борта:** отрезки + губки луз (короткие отрезки/дуги). Отскок с упругостью; боковой винт немного меняет угол отскока.
- **Лузы:** окружности захвата. Если центр шара вошёл в окружность захвата лузы — шар забит. Плюс отдельная механика «дрожание в губках» (шар ударился в губку рядом с лузой на малой скорости) — это событие для антититула.
- **Прыжки:** при `elevation` выше порога и достаточной силе биток получает `vz`. Пока `z > radius`, столкновения с шарами на столе пропускаются (перепрыгивает). Приземление с затухающим отскоком. Борта ловят шар в воздухе как обычно (упрощённо).
- **Массе (кривая):** при большом `elevation` и боковом винте возникает сила, перпендикулярная скорости, — шар идёт по дуге. Эффект затухает с вращением.
- **Окончание удара:** когда все шары неподвижны (скорости и вращения ниже порогов) или превышен лимит времени симуляции (`MaxShotSeconds`, ~15 с).

### 4.2. Точность и производительность

- **Без туннелирования.** На скорости 10 м/с при шаге 1/240 с шар проходит ~4 см — больше радиуса. Используй **непрерывное обнаружение столкновений (time of impact)**: внутри шага ищи ближайшее по времени событие (решение квадратного уравнения для пар шаров, пересечения с отрезками бортов), продвигай симуляцию до него, обрабатывай, продолжай. Либо фиксированный мелкий шаг с подшагами — но тогда докажи тестом, что туннелирования нет на максимальной скорости.
- **Широкая фаза** — пропускай пары неподвижных шаров.
- **Бюджет:** типичный удар (разбой включительно) должен считаться на сервере **быстрее 30 мс**. Добавь бенчмарк в тесты (в Lune) и выведи время.
- **Детерминизм:** одинаковые входные данные → одинаковый результат в одной среде. Не используй `math.random` внутри симуляции (если нужен шум — только с явным seed через `Random.new(seed)` на стороне вызывающего кода, а в чистом модуле — свой простой PRNG).

### 4.3. Выход симуляции

`PoolPhysics.simulateShot(state, shotParams, opts) -> SimResult`, где:

- `finalState` — финальные позиции и статусы шаров;
- `events` — список событий с временем: `CueStrike`, `BallBall {a, b, speed}`, `BallCushion {ball, cushionId, speed}`, `BallJaw {ball, pocketId}`, `Pocketed {ball, pocketId}`, `Airborne {ball}`, `Landed {ball}`, `Rattle {ball, pocketId}`;
- `frames` — ключевые кадры позиций (и высоты/ориентации для красивого вращения) с частотой `Config.Physics.RecordHz` (по умолчанию 60). Записывай только шары, которые двигаются в этом кадре.

`TrajectoryCodec` упаковывает `frames` + `events` в `buffer` (координаты квантуй, например, в int16 с шагом ~0.1 мм относительно центра стола) для отправки по сети. Нужен и декодер для клиента. Тест: encode → decode даёт те же данные в пределах квантования.

### 4.4. Тесты физики (обязательно)

- биток по прямой без шаров: останавливается, путь монотонно убывает по скорости;
- лобовой удар по неподвижному шару без винта: биток почти останавливается (stun), прицельный шар уходит;
- накат/оттяжка: после лобового удара с верхним винтом биток едет вперёд, с нижним — назад;
- отскок от борта: угол падения ≈ углу отражения без винта;
- туннелирования нет: биток на максимальной скорости не проходит сквозь шар и борт;
- забивание: шар, направленный в центр лузы, забит; шар, ударившийся о губку на малой скорости, не забит и даёт событие `BallJaw`;
- разбой: при максимальной силе по центру треугольника ≥ 4 шаров касаются бортов;
- детерминизм: два одинаковых прогона дают идентичный результат;
- бенчмарк разбоя < 30 мс (выведи фактическое время).

## 5. Прицел и управление

**Мобильные (горизонтально, `ScreenOrientation` = LandscapeSensor):**
- свайп по столу вращает кий вокруг битка;
- справа — колесо точной доводки угла (медленное вращение);
- слева — вертикальная шкала силы: тянешь вниз, отпускаешь — удар; отмена, если вернуть палец в исходную точку;
- кнопка «винт»: открывает биток крупно, точкой выбирается место удара (`spinX`, `spinY`); там же ползунок подъёма кия (`elevation`) для прыжков и массе (на ранних фазах можно скрыть за флагом);
- «шар в руке»: перетаскивание битка пальцем, сервер проверяет допустимость позиции (не пересекается с шарами, внутри поля, в «доме» после разбоя — если правило включено).

**ПК:** мышь — направление, колесо/клавиши — точная доводка, зажатие ЛКМ + оттягивание — сила; винт — отдельная панель.

**Прицельная линия (`AimPredictor`):** на клиенте, тем же кодом геометрии. Луч-окружность от битка до первого касания (шара или борта), «призрак» битка в точке касания, короткая линия направления прицельного шара и короткая линия отхода битка. Длина линий — из характеристик кия (`Config`), но в обучении и в рейтинге — фиксированная базовая (чтобы не было pay-to-win).

**Камера стола:** вид сверху почти ортографический (камера далеко, маленький `FieldOfView`, например 10–15), стол занимает экран с запасом под HUD. При посадке за стол — плавный переход от камеры аватара к камере стола; при выходе — обратно.

## 6. Правила 8-ball (`PoolRules`)

Чистые функции: `PoolRules.evaluate(matchState, simResult, shotMeta) -> RulesResult` (следующий игрок, фолы, назначение групп, ball-in-hand, конец игры и победитель, текстовый ключ причины).

- Разбой: легальный, если забит шар или ≥ 4 шаров коснулись бортов; иначе фол (в нашей версии — соперник получает «шар в руке», без переразбоя — проще для мобильных).
- Восьмёрка на разбое: **победа** (это «Небесный» титул) — настраивается флагом.
- Открытый стол до первого легально забитого шара после разбоя; затем назначаются группы (сплошные 1–7 / полосатые 9–15).
- Фолы: биток в лузе; первым задет шар не своей группы (или восьмёрка, пока группа не закрыта); не задет ни один шар; после касания ни один шар не коснулся борта и ничего не забито; биток вылетел со стола; превышено время хода.
- После фола — соперник получает «шар в руке» по всему столу.
- Восьмёрка — после закрытия своей группы, в **заказанную лузу** (перед ударом по восьмёрке игрок выбирает лузу тапом). Забил восьмёрку раньше, не в ту лузу или вместе с фолом — поражение.
- Таймер хода — `Config` (30 с), с сокращением при повторных просрочках.
- Вариант `Chinese8` — те же правила, другие параметры стола (узкие лузы) и визуал (красное сукно). Правила вынеси так, чтобы различия задавались данными.

**Тесты правил:** таблица сценариев (минимум 20): легальный/нелегальный разбой, назначение групп, каждый тип фола, победа/поражение на восьмёрке, просрочка времени и т.д.

## 7. Система хайпа: титулы и антититулы

### 7.1. ShotReport

После симуляции сервер строит `ShotReport` из событий и состояния: `isBreak`, `cueSpeed`, `power`, `spinX/Y`, `elevation`, `pottedCount`, `pottedOwnBalls`, `pottedEight`, `firstContactBall`, `cushionsBeforePot` (для каждого забитого шара — сколько бортов он коснулся до лузы), `potDistance` (путь шара), `cueAirborne`, `jumpedOverBall`, `curvedPath` (была ли дуга массе), `cleared` (очистил стол за один заход), `foulType`, `rattled` (дрожал в губках и не упал), `missedEverything`, `cueScratched`, `cueOffTable`, `snookeredOpponent` (у соперника нет прямой линии ни к одному своему шару), `turnStreak` и т.п.

### 7.2. Данные титулов — `Config/Titles.luau`

Титулы — **данные, а не код**. Пример схемы:

```lua
{
    id = "TIGER",
    kind = "Title",            -- "Title" | "Anti"
    priority = 100,            -- выбирается подходящий титул с наибольшим приоритетом
    hanzi = "虎虎生威",
    nameKey = "TITLE_TIGER",   -- ключ локализации: "ТИГРИНЫЙ УДАР" / "TIGER SHOT"
    rarityTier = "Common",
    spirit = "Tiger",          -- дух, которому идёт прогресс
    splash = "Tiger",          -- стиль заставки (ключ в Assets)
    sound = "TigerRoar",       -- ключ звука в Assets
    announcer = "AnnTiger",    -- ключ реплики комментатора
    slowMo = true,
    cameraShake = 0.8,
    conditions = { isBreak = true, minPotted = 1, minPower = 0.85 },
}
```

`conditions` — декларативный набор проверок над полями `ShotReport` (min/max/equals/bool). Если какому-то титулу нужна сложная проверка, допускается именованный предикат из реестра в `ShotClassifier` — но по умолчанию всё через данные.

### 7.3. Статистика редкости

- `HypeService` считает глобальные счётчики: сколько раз выпал каждый титул и общее число ударов. Используй `MemoryStoreService` (SortedMap/HashMap) с батчингом — инкременты копятся на сервере и сбрасываются раз в N секунд; периодически переноси в DataStore для долговременного хранения.
- На заставке показывай: «Только X% ударов становятся этим титулом» (или «1 из N»). Если данных мало (< порога) — не показывай процент.
- Ошибки MemoryStore/DataStore не должны ломать игру: заставка просто без процента.

### 7.4. Подача (клиент, `HypeController`)

1. На последнем значимом событии (обычно `Pocketed`) — замедление проигрывания траектории (time-scale в плеере), приближение камеры к лузе.
2. Заставка: огромные золотые иероглифы, название (локализованное) под ними, процент редкости, звук и реплика комментатора, частицы, тряска камеры (сила из конфига).
3. Заставки читаются **без звука** — крупный текст, яркий контраст.
4. Все звуки — через `Config.Assets` по ключу; если ID = 0 — заглушка (print + без звука).
5. Объявление на весь сервер для тиров Epic+; для Legendary — на все серверы через `MessagingService` (с ограничением частоты).

## 8. Режим клипа (вертикальный повтор)

После удара с титулом (или по кнопке «Клип» в течение N секунд после удара) клиент может запустить **повтор**:

- камера поворачивает стол **вертикально** (длинная сторона по вертикали экрана) — так стол заполняет кадр 9:16;
- интерфейс игры скрыт; поверх — крупный титул сверху и название игры (водяной знак) внизу;
- важное держится вне «опасных зон» рилсов: оставь отступы сверху ~12%, снизу ~20%, справа ~15% (константы в конфиге);
- повтор берёт тот же `frames` — переигрывание траектории, без новой симуляции;
- в конце повтора — короткий кинематографичный кадр с аватаром игрока (поза победы или реакция провала);
- кнопки: «Повтор ещё раз», «Сохранить скриншот» (через `CaptureService`, проверь актуальный API), «Закрыть».
- в горизонтальном экране телефона клип отрисовывай в вертикальной «рамке» по центру — игрок записывает экран и обрезает. Укажи это в подсказке на экране клипа.

## 9. Мир, столы и матчи

### 9.1. Мир

- Лобби в китайском стиле (пока — примитивы): фонари, красные столы, центр — большой **Тигриный стол** (Король стола), по краям — участки бильярдных-додзё игроков (по одному на игрока на сервере).
- Обычные столы для матчей с ботами и игроками.
- `Players.MaxPlayers` и количество участков — в конфиге (ориентир 8–12).
- `StreamingEnabled` — включить, следить, чтобы столы и участки корректно подгружались.

### 9.2. Столы (`TableService`)

- `ProximityPrompt` «Играть» у стола → игрок садится (аватар позиционируется у стола, анимация «склонился над столом» — заглушка), камера переходит в вид стола.
- Варианты: «Против бота» (сразу), «Против игрока» (очередь у стола или общая очередь сервера), «Король стола».
- Если за 20 с соперник-человек не нашёлся — предложить бота.
- Выход из матча = поражение (кроме выхода до первого удара).

### 9.3. Сетевой протокол удара

1. Клиент → `Shot:FireServer({angle, power, spinX, spinY, elevation, calledPocket?, cueBallPos?})`.
2. Сервер: проверка — матч активен, ход этого игрока, таймер не истёк, все числа конечные и в допустимых диапазонах, `cueBallPos` допустим (если «шар в руке»), лимит частоты.
3. Сервер: `PoolPhysics.simulateShot` → `PoolRules.evaluate` → `ShotClassifier` → награды/прогресс.
4. Сервер → обоим игрокам и зрителям (в радиусе стола): `ShotResult` с закодированной траекторией (`buffer`), событиями, итогом правил, титулом.
5. Клиенты проигрывают траекторию (интерполяция между кадрами, вращение шаров по направлению движения, звуки ударов по событиям с правильным временем и громкостью от скорости).
6. Сервер ждёт длительность траектории (+ время заставки, ограниченное сверху) и передаёт ход.

Все RemoteEvent/RemoteFunction описаны в одном месте (`Net/Remotes.luau`) с типами payload. На сервере — общий валидатор и `RateLimiter` для каждого remote.

### 9.4. Бот (`BotService`)

- Генерирует кандидатов: для каждого своего шара и каждой лузы — угол прямого удара (через «призрак»); добавляет варианты силы и винта; плюс безопасные удары (отыгрыш), если хороших нет.
- Оценивает кандидата симуляцией: забил ли свой шар, нет ли фола, позиция битка для следующего удара, риск оставить сопернику лёгкий шар.
- Сложности (`Easy/Medium/Hard`): количество кандидатов + шум по углу и силе.
- **Не блокировать сервер:** перебор распределяй по кадрам (корутины + `task.wait()`), ограничивай бюджет времени. Бот «думает» 1–3 с — это нормально и выглядит естественно.

### 9.5. Обучение (`TutorialController` + сервер)

Цель — **первый «Тигриный удар» в первые 30–60 секунд**.

- Новичок сразу попадает за стол против бота (можно пропустить).
- Первый разбой — **подстроенный**: фиксированная расстановка, авто-прицел; при любой силе ≥ порога сервер использует заранее найденные параметры удара, гарантированно забивающие шар. Эти параметры найди скриптом в Lune (перебор) и сохрани в конфиг; добавь тест, что они действительно дают титул TIGER.
- Дальше — 3–4 подсказки: прицел, сила, винт, «шар в руке». Всё через ключи локализации.
- Шаги обучения логируй в воронку аналитики (`AnalyticsService:LogOnboardingFunnelStepEvent`).

## 10. Прогрессия

### 10.1. Данные игрока (ProfileStore)

Схема с полем `schemaVersion` и функцией миграции. Ориентир:

```
coins, gems, xp, level, trophies, rating,

cosmetics { cues, tables, ballSets, announcers, emotes, splashSkins },

dojo { tables = {...}, upgrades = {...}, lastCollectTime, rebirths },

purchases { recentReceiptIds = {...} },  -- идемпотентность ProcessReceipt
settings { music, sfx, announcer, quality },
tutorialDone, firstJoinTime, lastOnlineTime
```

### 10.2. Духи ударов (`Config/Spirits.luau`, `SpiritService`)

- Каждый титул связан с духом (Тигр, Карп, Панда, Дракон, Журавль, Обезьяна, Змей, Феникс, Небесный…).
- **Открытие — навыком:** первый раз сделал титул → дух открыт. Каждый следующий титул даёт прогресс; уровни духа по порогам (например 1/5/20/50/150).
- Экипированный дух меняет **только косметику**: стиль заставки, след кия, голос комментатора. **Никакого влияния на физику.**
- Уровень духов влияет на доход бильярдной-додзё (раздел 11).
- **Индекс духов:** все духи, силуэты неоткрытых, подсказка «как открыть» (кроме секретных — «???»).

### 10.3. Кии

- Характеристики: длина прицельной линии, винт, сила, время хода.
- **В рейтинговом режиме характеристики кия не действуют** (у всех базовые), действуют только скины. В обычных матчах — действуют, но матчмейкинг по уровню кия/рейтингу.
- Кии покупаются за монеты, скины — за кристаллы/Robux.

### 10.4. Уровни, трофеи, рейтинг

- XP за удары/победы → уровень → открытие функций и столов.
- Рейтинг (Elo-подобный) — только для рейтингового режима.
- Лидерборды (`OrderedDataStore`): победы, рейтинг, доход додзё, «удар дня». Физические доски в лобби.

### 10.5. Ежедневное и задания

- Ежедневная награда с серией (7-дневный цикл).
- 3 ежедневных и 3 недельных задания из пула (например «сделай 2 титула Дракон», «выиграй 3 матча», «забей 10 шаров с винтом»).

## 11. Бильярдная-додзё (идл)

- У каждого игрока на сервере — участок-бильярдная (появляется при входе, исчезает при выходе).
- Столы покупаются и улучшаются за монеты. За столами играют NPC-ученики (простые анимированные модели-заглушки).
- **Доход в секунду** = Σ(базовый доход стола × уровень стола) × (1 + бонус от суммы уровней духов) × множитель ребёрта × множители геймпассов/бустов/событий. Формулы — в `Config/Dojo.luau`, тесты на формулы — в `economy.spec.luau`.
- Монеты копятся в «кассе» бильярдной; сбор — подойти к кассе (или автосбор по геймпассу).
- **Офлайн-доход:** при входе считается по `lastOnlineTime` с лимитом (8 ч, 24 ч с VIP), защита от отрицательного/огромного времени. Экран «Пока тебя не было…» с кнопкой «x2 за рекламу».
- **Ребёрт («Новый год»):** сброс монет и столов додзё → постоянный множитель. Требования: монеты + конкретные титулы (например, «сделай Дракона в рейтинговом матче»). Пороги — в конфиге.
- Улучшения декора (фонари, статуи духов, гонг) — небольшие множители + визуал.

## 12. Режимы

| Режим | Фаза | Суть |
|---|---|---|
| Против бота | 3 | обычный 8-ball, 3 сложности |
| Обычный PvP | 7 | 8-ball, характеристики киев действуют |
| Рейтинговый | 7 | чистый 8-ball, базовые кии, рейтинг |
| Король стола | 7 | центральный Тигриный стол: победитель остаётся, корона над головой, бонус к доходу додзё пока держит стол, фиксированная награда за каждую защиту, зрители смотрят на большом экране |
| Хаос-режим | 10 | 8-ball + шкала тигриного суперудара + бонусы с золотых шаров |
| Скоростной бильярд | 10 | два игрока бьют одновременно, без очереди |
| Трюк недели | 10 | фиксированная абсурдная расстановка, лидерборд по числу попыток |
| Песочница | 10 | расстановка шаров как угодно, без правил, скрытие UI, свободная камера — для авторов роликов |

**Хаос-режим, бонусы** (каждый — модуль-модификатор параметров физики/правил на один удар): гигантский биток, сужение луз сопернику, туман над столом (клиентский визуал), «землетрясение» (случайный небольшой импульс всем шарам), перевёрнутая гравитация для прыжка, раздвоение битка. **Тигриный суперудар:** шкала копится от титулов; полная — удар с увеличенной макс. скоростью и гарантированной заставкой TIGER.

**Скоростной бильярд** (самое сложное — делай последним): сервер ведёт симуляцию непрерывно (шаг 60 Гц с подшагами/TOI), принимает удары игроков, когда их биток неподвижен, рассылает состояние ~20 Гц, клиенты интерполируют. Потребует расширения `PoolPhysics` до пошагового API (`step(state, dt)`), не ломая `simulateShot`.

## 13. Монетизация

### 13.1. Валюты

- **Монеты** — зарабатываются в игре (матчи, додзё, задания). Продаются и за Robux, но ни в каких ставках не участвуют.
- **Кристаллы** — премиальные: продаются за Robux, понемногу даются за задания и события.

### 13.2. Геймпассы (`Config/Monetization.luau`, ID = 0)

- **VIP:** x2 монеты за матчи, офлайн-лимит 24 ч, тег, VIP-скин заставки.
- **x2 доход додзё.**
- **Автосбор** кассы додзё.
- **Свой Тигриный стол** в додзё (косметика + небольшой доход).

Проверка через `MarketplaceService:UserOwnsGamePassAsync` с кешем, и обработка `PromptGamePassPurchaseFinished` для мгновенного применения.

### 13.3. Developer Products (ID = 0)

- Пакеты кристаллов и монет; стартовый набор (одноразовый, флаг в профиле).
- Бусты: x2 монеты 30 мин, x2 доход додзё 30 мин.
- **«Хайп сервера»:** один игрок включает на 15 мин усиленные заставки и x2 награды за матчи для всех на сервере; объявление «ИГРОК включил Хайп сервера!». Не суммируется — продлевается.
- Скины: кии, сукно, наборы шаров, **голоса комментатора**, стили заставок, скины духов, эмоции после удара.
- **Подарки:** покупка буста/скина для другого игрока на сервере (выбор получателя в UI, выдача получателю).
- Награды за рекламу (раздел 14) — тоже developer products.

### 13.4. Единый `ProcessReceipt`

- **Только один** обработчик `MarketplaceService.ProcessReceipt` на всю игру — в `ShopService`. Роутинг по `ProductId` на хендлеры. Награды за рекламу приходят сюда же (`receiptInfo.ProductPurchaseChannel == Enum.ProductPurchaseChannel.AdReward`) — проверь актуальное имя поля по документации.
- Идемпотентность: если `PurchaseId` уже есть в `profile.purchases.recentReceiptIds` — вернуть `PurchaseGranted` без повторной выдачи. Выдача и запись ID — атомарно в профиле; `PurchaseGranted` — только когда профиль активен и изменение применено. Если игрока нет на сервере или профиль не загружен — `NotProcessedYet`.
- Логирование покупок в аналитику (`LogEconomyEvent`).

## 14. Реклама (Rewarded Video)

- Требования Roblox к игре и разработчику (порог посещений, верификация, анкета зрелости) выполняю я. В коде: если реклама недоступна — кнопки скрыты, всё работает без неё.
- **Клиент:** `AdService:GetAdAvailabilityNowAsync(Enum.AdFormat.RewardedVideo)` вызывается **в момент открытия** панели с рекламной кнопкой (не заранее). Кнопка видна только при `IsAvailable`. На кнопке — явный текст награды («Смотреть рекламу: x2 награда»).
- **Сервер:** по remote — проверка лимитов → `AdService:CreateAdRewardFromDevProductId(id)` → `AdService:ShowRewardedVideoAdAsync(player, reward, placementId?)` в `pcall` → результат клиенту. Награда выдаётся через `ProcessReceipt`.
- Сверь все имена методов и enum с актуальной документацией AdService.
- `AdService:RegisterAdOpportunityAsync` для учёта показов кнопок (если доступно).
- **Места (placements, ID в конфиге):**
  1. «x2 награда за матч» на экране результата;
  2. «x2 офлайн-доход» на экране входа;
  3. «x2 доход додзё на 10 минут»;
  4. «Ещё одна попытка трюка недели».
- Лимит показов на игрока в день — в конфиге. Реклама никогда не показывается во время хода.

## 15. Социальное и вирусное

- **Быстрый чат в матче:** набор готовых фраз и мемных стикеров (`Config/QuickChat.luau`, ключи локализации): «Hu hu sheng wei!», «Удачи…», «Это было специально», «Ещё раз?», рёв тигра и т.п. Лимит частоты. Показ над столом у отправителя.
- **Эмоции после удара:** рёв тигра, гонг, поклон, «танец победы» — аватар у стола (виден в клипе и в мире).
- **Объявления:** Epic+ на сервер, Legendary на все серверы (`MessagingService`, лимит частоты).
- **«Удар дня»:** лучший титул по редкости за день — глобальный лидерборд + доска в лобби.
- **Друзья:** +10% к наградам за каждого друга на сервере (макс. в конфиге), проверка `Player:IsFriendsWith` при входе (кеш). Кнопка «Пригласить» → `SocialService:PromptGameInvite`. Награда пригласившему, когда друг впервые зашёл по приглашению (проверь актуальный API launch data/приглашений).

- **Коды:** ввод из списка в live-конфиге (это не свободный текст для других игроков, фильтрация не нужна), одноразово на игрока.
- **Цель по лайкам** — только как общая цель на экране («10K лайков → новый код»), без индивидуальной награды за лайк.
- **Водяной знак** с названием игры — в режиме клипа (и опционально тонко в углу стола).

## 16. События (`EventService`, `Config/Events.luau`)

- Расписание считается от `os.time()` в UTC — **одинаково на всех серверах без координации**.
- **Мини-события** каждые 30 мин на 5 мин: «Золотой час» (x2 монеты), «Тигриная ночь» (усиленные заставки, x2 прогресс духов), «Дождь фонарей» (бонусные монеты в лобби).
- **Еженедельный ивент** в фиксированное время (например, суббота 18:00 МСК): я как админ запускаю эффекты через админ-команды (только для `UserId` из конфига): «все удары — тигриные», дождь золотых шаров, x3 награды. Админ-команды — через отдельный remote с проверкой UserId на сервере.
- **Праздники** (по датам в конфиге): Новый год по лунному календарю, Праздник фонарей, Праздник лодок-драконов — тематические скины и задания.
- Таймер «До события / до обновления» на доске в лобби.

## 17. Live-конфиг (`LiveConfigService`)

Чтобы реагировать на новые мемы без перепубликации:

- Ключ в DataStore `LiveConfig` (JSON): включённые/выключенные титулы, переопределения текстов титулов, активные коды, переопределения расписания событий, флаги функций, баннер новостей.
- Сервер читает при старте и раз в 5 минут; плюс мгновенное обновление по `MessagingService`.
- **Безопасно:** валидация схемы, при ошибке — значения из `Config`.
- Новые **ассеты** (звуки, картинки) всё равно требуют загрузки в Roblox и ID в конфиге — live-конфиг может ссылаться только на ключи ассетов, которые уже есть в `Config/Assets.luau` (плюс опциональный список дополнительных ID, проверенных мной).
- Опиши в `docs/` формат JSON live-конфига и как его менять (скрипт для командной строки Studio).

## 18. Аналитика (`AnalyticsService` Roblox)

Обёртка-сервис, все вызовы в `pcall`:
- воронка обучения (`LogOnboardingFunnelStepEvent`): вошёл → сел за стол → первый удар → первый тигр → закончил матч → открыл додзё;
- экономика (`LogEconomyEvent`): источники и траты монет/кристаллов;
- прогресс (`LogProgressionEvent`): уровни, ребёрты;
- кастомные (`LogCustomEvent`): титулы по типам, открытие клипа, нажатие «скриншот», использование быстрого чата, показ/просмотр рекламы.

Проверь актуальные сигнатуры методов по документации.

## 19. Интерфейс, локализация, производительность

- **Мобильный UI в первую очередь:** крупные кнопки (минимум ~44 pt), безопасные зоны (`GuiService:GetGuiInset`, `ScreenGui.SafeAreaCompatibility`/`ScreenInsets`), масштабирование через `UIScale` и `AnchorPoint`/Scale-размеры.
- Стиль: красный/золотой/чёрный, крупная каллиграфия для титулов (шрифт — какой доступен в Roblox; конкретный выберу я).
- **Локализация:** `LocalizationTable` с ключами (en, ru), генерируй таблицу из Luau-модуля `Config/Strings.luau`, чтобы было удобно редактировать.
- **Производительность:** мало инстансов (шары — простые Part/MeshPart), никаких лишних `RenderStepped`-подписок, частицы с лимитом, качество эффектов зависит от настройки игрока и `UserGameSettings.SavedQualityLevel`.
- Звук: настройки «музыка/эффекты/комментатор» отдельно. **Важно для рилсов:** в момент заставки музыка приглушается, остаются только резкие эффекты удара — авторам проще наложить свою музыку.

## 20. Безопасность

- Все remote — валидация типов (`typeof`, `math.isfinite`-аналог, диапазоны), принадлежности (это твой ход/твой стол/твой участок), лимит частоты.
- Никаких значений наград, цен и результатов с клиента.
- Админ-функции — только для UserId из конфига, проверка на сервере.
- Выход игрока посреди матча/покупки — корректная обработка (поражение / `NotProcessedYet`).
- Ни одного `loadstring`, никаких `require` по ID ассета.
